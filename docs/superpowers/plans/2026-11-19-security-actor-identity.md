# Prioritas 1: Tutup Celah Keamanan & Identitas Aktor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mengamankan sistem SisaBerkah dengan middleware Next.js berbasis cookie sesi, menghentikan pembobolan rute admin oleh relawan/pengguna publik, menghapus hardcoded admin ID pada seluruh route handler agar aksi relawan tercatat atas nama mereka sendiri, serta mengunci endpoint `/api/users` hanya untuk ADMIN.

**Architecture:** 
1. `src/lib/auth-edge.ts` menyediakan verifikasi JWT HS256 yang 100% kompatibel dengan Next.js Edge Runtime menggunakan standard Web Crypto API (`crypto.subtle`) tanpa dependensi Node `crypto`/`bcrypt`.
2. `src/middleware.ts` memproteksi rute halaman (Next.js middleware): pengunjung tanpa cookie `sb_session` yang valid dialihkan ke `/login`, relawan biasa yang mencoba membuka rute admin (`/pengguna`, `/makanan/kelola`, `/laporan`) dialihkan ke `/dashboard`, dan pengguna yang sudah login yang mengunjungi halaman login/register dialihkan ke `/dashboard`.
3. `src/lib/auth.ts` diekstensi dengan helper `getSessionUser(req?: Request)` yang membaca sesi baik dari Next.js `cookies()` store maupun header `Cookie`/`Authorization` (kompatibel untuk production runtime dan testing context).
4. Route handlers (`/api/food/inbound`, `/api/distributions`, `/api/distributions/[id]/status`, `/api/food/correct`, `/api/food/dispose`, dan `/api/users`) menggunakan identitas user autentikasi asli dan menolak akses tak berizin dengan status HTTP 401/403.

**Tech Stack:** Next.js 15 (App Router), TypeScript, Web Crypto API (`crypto.subtle`), Prisma ORM, Vitest.

**Spec:** Sesuai instruksi USER_REQUEST:
1. Pasang `src/middleware.ts` Next.js membaca cookie `sb_session`.
2. Hapus hardcoded Admin ID di semua endpoint API, gunakan token sesi cookie (`verifySessionToken`).
3. Kunci endpoint `/api/users` hanya untuk role `ADMIN`.

## Global Constraints

- Sesi disimpan dalam cookie HTTP `sb_session`.
- Role pengguna: `ADMIN` atau `RELAWAN` (enum `Role` dari Prisma).
- Rute halaman khusus admin: `/pengguna`, `/makanan/kelola`, `/laporan`.
- Middleware Next.js harus kompatibel dengan Edge Runtime (tidak boleh mengimpor modul Node core `crypto` atau `jsonwebtoken`/`bcryptjs`).
- Seluruh tes yang ada (108 tes di 18 test file) harus tetap lulus, ditambah tes baru untuk memverifikasi keamanan dan identitas aktor.

## Review Focus

1. Edge Runtime Incompatibility: Modul `jsonwebtoken` mengimpor `crypto` internal Node.js sehingga crash di Next.js middleware Edge Runtime. Plan menyediakan `src/lib/auth-edge.ts` dengan Web Crypto API.
2. Request Context di Unit Test: Pemanggilan route handler langsung di Vitest (e.g. `InboundFoodRoute.POST(req)`) tidak memiliki context `next/headers cookies()`. `getSessionUser` harus membaca fallback dari `req.headers.get('cookie')` dan `req.headers.get('authorization')`.
3. Relawan Identity Preservation: Relawan yang login saat mencatat makanan masuk (`/api/food/inbound`) atau memperbarui status distribusi (`/api/distributions/[id]/status`) harus tercatat dengan `userId` relawan, bukan admin pertama di database.
4. Unauthorized / Forbidden Status Codes: Request tanpa sesi mengembalikan 401 Unauthorized; request dengan sesi relawan ke endpoint khusus admin mengembalikan 403 Forbidden.
5. Path Matching Middleware: File statis (`_next`, `favicon.ico`, gambar) dan endpoint API (`/api/*`) tidak boleh dialihkan ke HTML `/login`.
